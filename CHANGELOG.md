# Changelog

All notable changes to this project are documented here. The format is
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**Byte-output changes — a bumped resvg, pngquant or oxipng, or any pipeline change — are
minor at minimum, never patch.** Downstream users diff these files into git.

## [Unreleased]

### Added

- `favcon/astro`: an Astro integration. Builds in `astro:build:start` so Astro's ordinary
  `public/` copy carries the files to `outDir` — correct for static output and for every SSR
  adapter. Head tags via an `order: 'post'` middleware, a `<Head />` component, or logged for
  pasting.
- A content-addressed build cache for the integration, keyed on favcon's version, the input
  bytes, the canonicalised options **and** the `--version` strings of resvg, pngquant and
  oxipng — so a `brew upgrade` invalidates it instead of silently serving stale bytes.
- The integration refuses to overwrite a file in `public/` it did not write itself, checked by
  content rather than by filename. A file that already matches what it was about to write is
  left alone, so a clean install does not accuse you of hand-editing your own favicon.
- `build()`, `optimiseSvg()`, `icoWrap()`, `toolPath()`, `toolVersions()` and `FavconError`
  are exported. `build()` throws; the CLI still exits.
- `test/run.mjs`: the definition of done as `node:test`, with a PNG reader and an accuracy
  gate written over `node:zlib`. No bash, no ImageMagick.
- `bench/bench.mjs`: sweeps palette size, dither, stage order, zopfli iterations and the ICO
  container over `test/fixtures/`, and regenerates `docs/BENCHMARKS.md`.
- Twelve neutral fixtures, authored here. `heavy.svg` is generated by a committed script and
  calibrated to fail at `floatPrecision: 0` and pass at `1`.
- CI on `ubuntu-24.04` (pinned), `macos-15` and a `windows-latest` smoke job.

### Changed

- **`--sizes` now defaults to `192 512`, was `256 512`.** Chrome's installability check
  matches the declared `sizes` token rather than the pixel dimensions, so a manifest with no
  literal `192x192` entry can silently fail to offer a PWA install prompt. `--sizes "256 512"`
  restores the old ladder. This renames an output file: `icon-256.png` becomes `icon-192.png`.
- **`--bg` now defaults to `#000000`, was `#ffffff`.** iOS composites a transparent Home
  Screen icon onto black, so black is what the platform would have produced anyway; the
  default now says so instead of substituting white. A mark drawn on a light ground wants
  `--bg '#fff'` — and the warning when the flag is absent has always been there to ask.
- `svgo` is imported rather than spawned, and the plugins are plain objects. Removes a temp
  config directory, ~110 lines of stringified plugin source, an env-var channel and two Node
  startups. Output is byte-identical.
- Tool resolution is pure Node: four tiers (`FAVCON_*` override, `pngquant-bin`,
  `node_modules/.bin` walking upwards, then `PATH` + `PATHEXT`), every candidate probed with
  `--version`, and every missing tool reported at once with its install line.
- `oxipng` is invoked with `--zopfli`, not `-Z`. oxipng 10.0.0 renamed the short form to
  `-z` and kept `-Z` only as an undocumented alias; the long form is correct on 9.x and 10.x.
- Errors are prefixed `favcon:` (was `favicon.mjs:`).

### Fixed

- **Non-square marks produced non-square rasters.** resvg does not stretch to fill `-w N -h N`
  — it preserves the aspect ratio and derives the second dimension, so a 128×64 mark came out
  32×16 and the ICO header disagreed with its own payload. `icon.svg` now carries a square
  intrinsic size and `preserveAspectRatio="none"`; `logo.svg` keeps its real proportions.
- **`icoWrap` validates its payload's IHDR** and refuses to write a header that disagrees
  with it, which is what turned the bug above from a silently wrong file into a failed build.
- **An animated mark could not be built at all.** svgo 4.1.0 crashes with
  `Unmatched selector: %` on `@keyframes` nested inside another at-rule — the exact shape the
  animated-input contract requires. favcon hoists nested `@keyframes` to the top level of the
  same stylesheet, where svgo's parser already skips them correctly.
- **An animated `logo.svg` silently lost its animation.** `inlineStyles` deletes the `class`
  attribute it consumed without checking whether a media-guarded rule still selects it, and
  csso then drops the now-unused `@media` block. `inlineStyles` is switched off for the logo
  pass, and only for a mark where some name is selected by both an inlinable rule and a
  non-inlinable one — the usual shape, with the motion class named only inside the guard,
  keeps the full inlining and the same bytes it has always had.
- A `pngquant-bin` shim whose binary was never downloaded no longer fails the build with a
  Node stack trace: a candidate that does not run falls through to the next tier.

### Removed

- The `icotool` dependency. favcon writes the 22-byte ICO container itself, byte-identical to
  `icotool -c -r` on every fixture. `icoutils` is now only a test-time nicety.
