# favcon

One SVG in, an optimised favicon set out.

```
npx favcon logo.svg --out public
```

This file is the specification and the build-out brief. Sections 1–7 describe the tool as it
**already is** — that behaviour is measured, tested, and must not regress. Section 8 is the work
that turns it into a published package. Section 9 is the contract every change is held to.

> **Status: section 8 is built.** Where the build-out found the spec to be wrong about
> something, `docs/DECISIONS.md` records what was measured and what changed — decisions 16–19.
> The three that matter most: resvg does *not* stretch a non-square mark to fill `-w N -h N`;
> svgo 4.1.0 both crashes on and silently mangles the animated-input shape §4 requires; and
> `--colors 8` misses the accuracy bar on the ramp-heavy fixtures and ships anyway, as a
> stated trade rather than an oversight (decision 19).
> `--sizes` now defaults to `192 512` and `--bg` to `#000000` (decisions 10 and 11, both
> deliberate reversals of what §1 and §3 originally said), and every PNG except the ICO
> payload is placed in the safe zone (decision 20) — one padded set declared `"any maskable"`,
> with the padding measurable per mark (`auto`, the default) or fixed (`--padding`, decision 22).
> `docs/BENCHMARKS.md` is regenerated by `node bench/bench.mjs --write` and supersedes every
> byte figure below.

## 1. What ships

| File | What it is |
|---|---|
| `logo.svg` | The mark itself. Optimised, **animation intact**. For pages and READMEs. |
| `icon.svg` | The same optimisation **plus a structural animation strip**. This is the browser favicon *and* the file every raster below is rendered from. |
| `favicon.ico` | One 32×32 entry, stored as a raw PNG in a 22-byte container. |
| `apple-touch-icon.png` | 180×180 on the `--bg` ground, the mark placed in the W3C safe zone and snapped to whole pixels. |
| `icon-<size>.png` | On the `--bg` ground, the mark placed in the safe zone the same way (`--padding`, default `auto`). Default 192 and 512. The manifest's `any maskable` icons. `icon.svg` is never listed: it breaks Android WebAPK installs. |
| `site.webmanifest` | Only with `--manifest`. Icons only — the user merges their own `name`/`theme_color`. |

### Flags

```
-o, --out DIR     Output directory (default: current)
    --colors N    Palette size, 2-256 (default: 8)
    --sizes LIST  Padded "any maskable" PNG sizes (default: "192 512")
    --bg COLOR    Ground of the padded icons (default: #000000). "none" keeps the set
                  transparent and unpadded, declared "any" only.
    --padding P   Margin of each padded icon, as a percentage per side (default: auto).
                  `auto` measures the mark's own extent and snaps it to whole pixels;
                  give a number to override it.
    --var N=V     Set a CSS custom property, e.g. --var brand=#0E7C68. Repeatable.
    --no-animation  Build logo.svg static too, so it equals icon.svg.
    --manifest    Also write site.webmanifest.
    --html        Print the <link> tags.
-q, --quiet   -V, --version   -h, --help
```

Long options also accept `--opt=value`; `--` ends option parsing. A flag that takes no argument
rejects one.

## 2. The five things that look wrong until you know why

- **resvg cannot read `var()`.** It does not error — it renders the whole mark **black** with a
  warning on stderr. Custom properties are resolved before anything is rasterised.
- **Quantise before recompressing.** pngquant re-encodes from scratch, so any order ending in
  pngquant throws away everything oxipng did.
- **An ICO holding a PNG is a 22-byte header plus that PNG verbatim**, so nothing can be optimised
  after packing. The payload must be final before it goes in.
- **Zopfli runs once**, on the file that already won the lossy/lossless comparison. Running it on
  both sides costs three times as much for identical bytes.
- **The rasters are built serially on purpose.** See decision 13.

## 3. Measured decisions

Every row is backed by a measurement. **The byte figures below were measured over a 39-mark
corpus that does not ship with this repo.** They are recorded as the reasoning that produced each
choice; re-measure against `test/fixtures/` before citing a number in the README, and regenerate
`docs/BENCHMARKS.md` rather than copying these.

**Accuracy bar.** `pct <= 1.0 %` — the share of pixels whose colour distance from the reference
exceeds 8/255, measured on **both** a white and a black composite, so alpha error cannot hide.
Reference = an unquantised resvg render of the var-resolved source at the same size. RMSE is
reported alongside but does not gate: error is driven by *size*, not by the mark, so one RMSE
threshold is the wrong shape — at 16 px nearly every pixel is an anti-aliasing edge.

**Priority.** Smaller output beats faster build.

| # | Decision | Evidence |
|---|---|---|
| 1 | **One file, ESM, Node.** `svgo` is a dependency and is **imported**; the plugins are plain objects in the same file. | Importing removes a `mkdtemp` config directory, ~110 lines of `String.raw` stringified plugin source that no linter or editor can see into, an env-var channel (`FAVICON_VARS`/`MODE`/`REPORT`), and two Node startups. Output is byte-identical: same svgo, same plugin list, same params. A *globally installed* svgo is not importable by bare specifier (`ERR_MODULE_NOT_FOUND`; `NODE_PATH` does not work for ESM) — as a package dependency it is. |
| 2 | **`var()` is resolved by a custom plugin listed first**, before `inlineStyles`/`minifyStyles`. | Byte-identical to a separate pre-pass, with one fewer parse. Handles nested fallbacks and values containing `/ & , ( )`, spaces and quotes; **fails loudly** on an unresolvable property. |
| 3 | **resvg never sees `var()`.** | resvg 0.48.1 has no `var()` support — it warns and renders the mark **entirely black**. Rasters come from the final `icon.svg`. |
| 4 | **icon.svg plugins:** `preset-default` + `convertStyleToAttrs` + `removeAttrs{(role\|aria-.*\|data-.*\|class)}` + `removeDimensions` + `removeTitle` + `removeDesc`, `multipass`. | `preset-default` alone leaves `aria-label` and turns the stylesheet into `style="fill:…"`. `convertStyleToAttrs` fixes the second, `removeAttrs` the first. `removeViewBox` is excluded **explicitly**, not left to the preset: it is absent from preset-default in svgo 4 but present in svgo 3, where an input carrying `width`/`height` matching the viewBox would lose the viewBox and then the dimensions, leaving an SVG that cannot scale. |
| 5 | **`floatPrecision: 1`.** | 7490 B vs 7996 B at the svgo default of 3 (−6.3 %), at pct 0.0965 % — ten times inside the bar. `floatPrecision 0` is 6030 B but **fails** at 1.0233 %. |
| 6 | **PNG: `pngquant --speed 1 --nofs --colors N`, then `oxipng`.** (`N` defaults to **8**; it misses the accuracy bar on ramp-heavy marks and ships anyway — see decision 19 in docs/DECISIONS.md.) | Quantise-then-recompress is mandatory (see §2). `--nofs` beats every dither setting on bytes and still passes. `--speed 1` is smallest *and* most accurate. `--posterize` is rejected — its least aggressive legal value (4) already misses the bar. |
| 7 | **Keep whichever of the lossy and lossless paths is smaller.** | Inert at the default `--colors 8` (lossless wins 0/90 files), but at `--colors 32` lossless wins **13/18 at 16 px** and the guard saves 4 %. Stops a raised `--colors` from silently producing *larger* files. |
| 8 | **Zopfli runs once, on the winner of that comparison**, at `--zi 120`. | Zopfli-ing both paths triples the cost for zero extra bytes: decide with the cheap `-o max -s` pass, then zopfli only the winner — same bytes, 3.7× faster. Iterations: 79665 B at the default 15, 79454 at 60, 79386 at 120. The curve is flattening (−0.27 %, then −0.09 %) but bytes ship forever and build time does not. **Use the long flag `--zopfli`:** oxipng 10.0.0 changed the short form from `-Z` to `-z`, and `-Z` survives only as an undocumented compatibility alias. Verified on 10.2.1 — `-Z` and `--zopfli` produce identical bytes today, but only the long form is safe on both 9.x and 10.x. |
| 9 | **`favicon.ico`: one 32×32 entry, raw PNG payload, container written in JS.** | BMP entries are **16.7× larger** (77 148 vs 4 611 B over the corpus), and `-b` below 32 silently drops alpha. Paletted PNG inside an ICO was **verified to decode** in headless Chromium and Firefox. The 22-byte container written in JS is **byte-identical to `icotool -c -r` on 39/39 builds** (verified 2026-09-12), which removes the only dependency with no npm package and no Windows build. See §5 for the exact layout. |
| 10 | **`--bg` defaults to opaque black**, with a stderr warning when it is not given, **validated by probing resvg** (a 1×1 render, ~3 ms) rather than by a colour table. | iOS composites transparent Home Screen icons onto **black**. Opaque is also 0.3 % *smaller* (no tRNS, simpler palette). Probing means `rgb()`, `rgba()` and `hsl()` all work and the validator can never disagree with the renderer — a name list rejects `rgb()`, and a loose `/^[A-Za-z]+$/` accepts `nonered`. Applies to every padded icon. Corners stay square; the OS applies its own mask. |
| 11 | **`--sizes` defaults to `192 512`.** *(Reversed — see decision 11 in docs/DECISIONS.md.)* | web.dev's install criteria, Chrome's docs and MDN all require a 192 and a 512 `any` icon. Desktop Chromium's code accepts one of 144 px or more, but one engine is not the contract; the documented pair wins. `--sizes "256 512"` restores the old ladder. |
| 12 | **The SVG is emitted twice: `logo.svg` keeps the animation, `icon.svg` never has it.** Both get the identical optimisation; `icon.svg` additionally gets the structural strip and is the file every raster is rendered from. `--no-animation` builds `logo.svg` static too. A source with no animation gets `logo.svg` as a byte copy of `icon.svg`. | Over 39 marks: every one of the **156 rasters is byte-identical** to the pre-split build, and `icon.svg` is the smaller of the two on **39/39** — by +188 B to +639 B, mean +284 B; `logo.svg` averages 7.6 % of a complete 4917 B set. Publishing the stripped copy costs nothing (it was already being built) and removes the one thing the single-file layout got wrong: a favicon `<link>` pointing at a file carrying `<style>`, `@keyframes` and classes that no rasteriser and no ICO can use. |
| 13 | **The rasters stay serial.** Concurrency is spent on the two svgo passes and the `--bg` probe instead. | Zopfli is ~98 % of wall clock (512 px 7.25 s, 256 px 3.31, 180 px 3.23, 32 px 0.03), so overlapping it looked obvious — it is not, because **oxipng already saturates the machine on a single file** (12.8 s wall for 1 m 30 s of CPU on 16 cores). Traced with timestamps: serially the 512 px job takes 9.1 s and the build 13.1 s; run four-up, the 512 px job alone stretches to 13.6 s and the build finishes at 13.6 s. Four interleaved reps each: **13.80 s serial vs 14.08 s concurrent**. A `-t` sweep (2/4/6/8/10/12/16) moved contention around without beating it. The pool, the ordering heuristic and the `AbortController` were all removed again. What *is* idle during single-threaded startup is 15 of 16 cores: **0.894 s → 0.456 s** for the two svgo passes. |
| 14 | **One render per distinct (size, background).** | Since the set collapsed to one padded set, `--sizes 32` renders twice: `(32, bg)` for `icon-32.png` and `(32, null)` for the ICO payload, for different bytes. Under `--bg none` the icon is unpadded too, so the two share one render and "the ICO payload is `icon-32.png`" holds again — by construction rather than by coincidence, as before. |
| 15 | **External binaries: `resvg` and `oxipng` are documented installs; `pngquant-bin` is an `optionalDependency`; `svgo` is a real dependency.** | No npm package can deliver resvg or oxipng. `resvg-cli` (404 weekly downloads) uses `--fit-width`, not `-w`, and pins resvg 0.34 against our 0.48.1. `oxipng` on npm is **1.0.1 from 2021** (wrapping oxipng 4.0.3) and `oxipng-bin` wraps 8.0.0 — **neither has `--zi`**, so wiring them up would silently produce larger files. `pngquant-bin` (211k weekly) works but its postinstall chain runs packages last published in 2017–2018 and it has no `linux/arm64` or `darwin/arm64` prebuilt — optional, so a failed install is a warning rather than a broken `npm i`. |

## 4. Animated input contract

What an animated source must follow, and what `--no-animation` relies on:

- **The geometry as drawn is the rest frame.** Nothing is positioned by a keyframe, so resvg,
  `--no-animation` and a reduced-motion viewer all see the same mark.
- **Motion lives inside `@media (prefers-reduced-motion:no-preference){…}`.** Everything inside
  such a block is treated as motion and removed wholesale — including a `reduce` block that exists
  only to switch motion off.
- **Iterations are `var(--loop, infinite)`** (an entrance starting from an empty frame uses
  `var(--loop, 1)`). Every keyframe set ends on the rest frame, so `--var loop=1` plays once and
  stops on the static mark.
- Each palette class is used **once** per file, so svgo can inline it. Where several shapes share
  a colour, the class goes on a wrapper `<g>`.

The strip is **structural**, not a regex over the file: SMIL elements (`animate`, `animateMotion`,
`animateTransform`, `animateColor`, `set`, `discard`), `@keyframes`, any `@media` mentioning
`prefers-reduced-motion`, and `animation*`/`transition*` declarations wherever they are — in rules,
in nested at-rules, and in `style=""`. Rules left empty are dropped. CSS is only rewritten when
something was actually removed, so a static input reaches `preset-default` byte-for-byte.

Because an animated `logo.svg` keeps its `<style>`, `removeAttrs class` would delete the very
classes the motion rules select. The `logo.svg` pass therefore swaps it for a `pruneRefs` plugin:
keep exactly the classes a selector names and the ids something references, drop the rest. SMIL can
name an id in `begin="x.end"`, which no pattern would catch, so id pruning is skipped entirely when
SMIL is present.

## 5. Pipeline

```sh
# 1. input.svg -> icon.svg + logo.svg   (two svgo runs, in parallel)
#    plugins: [resolveVars, preset-default{removeViewBox:false}, convertStyleToAttrs,
#              removeAttrs{(role|aria-.*|data-.*|class)}, removeDimensions,
#              removeTitle, removeDesc],  multipass: true, floatPrecision: 1
#    icon mode: stripAnimation runs FIRST (so a var() used only by an animation cannot
#               fail a build that discards it). This output is what every raster uses.
#    logo mode: no stripAnimation; removeAttrs without `class`; + pruneRefs.
#    --no-animation skips the logo run; logo.svg is then a copy of icon.svg, as it also
#    is when the icon run found no animation to strip.

# 2. icon.svg -> a PNG at size N        (apple-touch-icon adds --background "$BG")
resvg --quiet -w N -h N icon.svg raw.png
pngquant --force --speed 1 --nofs  --colors "$COLORS" --output nofs.png  raw.png
pngquant --force --speed 1 --floyd=1 --colors "$COLORS" --output floyd.png raw.png
oxipng -q -o max -s -a nofs.png floyd.png            # and a plain copy of raw.png
#   -a in this pass too, so the size comparison is like-for-like
#   keep whichever of the three is smallest (strictly smaller wins, so a tie keeps the
#   earliest — deterministic rather than incidental to iteration order), then:
oxipng -q -o max -s --zopfli --zi 120 -a winner.png
#   One job per distinct (size, background), run one at a time (decision 13).
#   pngquant exit 98 ("would be larger") and 99 ("below quality floor") are ordinary
#   outcomes — fall through to the lossless candidate. Match on the CODE, never the
#   message: 25 = cannot decode, 26 = cannot read, and those must not be swallowed.

# 3. icon-32.png -> favicon.ico         (written in JS, no icotool)
```

### The ICO container, exactly

Verified identical across 39 builds:

```
00 00 | 01 00 | 01 00 | 20 20 00 00 | 01 00 | 20 00 | <size u32le> | 16 00 00 00 | <png…>
```

| off | size | field | value |
|---|---|---|---|
| 0 | u16le | `idReserved` | 0 |
| 2 | u16le | `idType` | 1 (ICO) |
| 4 | u16le | `idCount` | 1 |
| 6 | u8 | `bWidth` | 32 — **0 means 256** |
| 7 | u8 | `bHeight` | 32 — **0 means 256** |
| 8 | u8 | `bColorCount` | 0 |
| 9 | u8 | `bReserved` | 0 |
| 10 | u16le | `wPlanes` | 1 |
| 12 | u16le | `wBitCount` | **32, always** |
| 14 | u32le | `dwBytesInRes` | `png.length` |
| 18 | u32le | `dwImageOffset` | 22 |

**`wBitCount` is the one to get wrong.** Across the 39 builds the payload IHDR is 2/3, 4/3, 8/3 or
8/6 — four different bit-depth/colour-type pairs — and icotool wrote `wPlanes=1, wBitCount=0x0020`
for **every one of them**. The directory entry describes the *decoded* 32-bit image, not the
encoding. Deriving it from the PNG's IHDR produces a file icotool never writes. Same for
`bColorCount = 0` on a genuinely paletted payload. Assert `px <= 256`; anything larger is
unrepresentable.

`bin/`, not root: a root-level `favcon.mjs` reads as "the package's main module", which it is not.

### package.json contract

- `"type": "module"`, `"license": "MIT"`, `"bin": {"favcon": "bin/favcon.mjs"}`
- `"engines": {"node": ">=22.12"}` plus `.npmrc` with `engine-strict=true`, so the failure is a
  clear message rather than a syntax error. 22.12 is the floor for stable `import.meta.resolve`.
- `"files": ["bin", "lib", "astro", "README.md", "LICENSE", "CHANGELOG.md"]` — `lib/` is not
  optional: `bin/favcon.mjs` imports it, so a tarball without it throws `ERR_MODULE_NOT_FOUND`
  on first run. `test/`, `docs/`, `bench/`, `site/` and `.github/` must never reach the tarball.
- `"dependencies": {"svgo": "^4.1.0"}`
- `"optionalDependencies": {"pngquant-bin": "^9.0.0"}`
- `"peerDependencies": {"astro": "..."}` with `peerDependenciesMeta.astro.optional = true` — a
  CLI-only user must not be nagged about Astro.
- `"keywords"` **must include `astro-integration`** — the token the Astro integrations directory
  indexes on.
- `"publishConfig": {"access": "public", "provenance": true}`
- `"exports"`: `"."` → `bin/favcon.mjs`, `"./astro"`, `"./astro/middleware"`,
  `"./astro/Head.astro"`, `"./package.json"`.

**Licence note.** favcon is MIT. pngquant is GPL-3.0+ and resvg is MPL-2.0, but favcon only
*spawns* them across a process boundary — mere aggregation, no linking. This changes the moment a
binary is vendored into a `@favcon/*` package; that package would have to be GPL-3.

## 7. Astro integration

```js
// astro.config.mjs
import favcon from 'favcon/astro'
export default defineConfig({ integrations: [favcon({ input: 'src/logo.svg' })] })
```

Options mirror the CLI, with `sizes` a real array and `vars` an object — that is what the flags
*mean*; the string forms exist only because argv is strings. `manifest` may take an object
(`name`, `short_name`, `theme_color`, …); the CLI writes icons-only because a CLI cannot know the
app's name, but an integration can. The merge happens in `astro/index.mjs`; the CLI gains nothing.

- **Bail immediately** on `command === 'sync' || command === 'preview'`.
- `astro:config:setup` only resolves paths, `addWatchFile`s the input, and registers middleware.
  **It must not build** — it runs on every dev-server restart.
- **`astro:build:start`** does the build, so Astro's ordinary `public/` copy carries the files to
  `outDir` for free — correct for static output *and* every SSR adapter. Building in
  `astro:build:done` means writing into `dir` by hand and getting it wrong for adapters that
  post-process `dist/`.
- **Output goes to `public/`.** In dev there is no build dir, and these files need fixed root URLs
  (`/favicon.ico`, `/apple-touch-icon.png`). Refuse to overwrite a `public/favicon.ico` the
  integration did not itself write — silently clobbering a hand-tuned ICO is the worst possible
  first impression.

**Not re-running the ~13 s build is a content-addressed cache, not a heuristic.**
`node_modules/.cache/favcon/<sha256>/`, keyed on favcon's version + the input bytes + canonicalised
options + **the `--version` strings of resvg, pngquant and oxipng**. That last part is what makes
it correct: all three change output bytes across versions, so a cache keyed only on the SVG hands
back stale bytes after `brew upgrade`, invisibly. On a hit, hardlink-or-copy into `public/` —
single-digit milliseconds.

For the genuinely cold first run, `dev: 'fast'` (default) builds one 256 px size with zopfli off:
under 1 s instead of ~13 s, since zopfli is ~98 % of wall clock. Dev artefacts are deliberately not
the production bytes. `'skip'` and `'full'` are the other two modes. This needs an internal
`zopfli: false` on `build()` — **an API option, never a CLI flag**.

**Head tags.** Astro has no official head-injection hook — all four `injectScript` stages are
JavaScript. So offer three modes: `'inject'` (default; an `order: 'post'` middleware that splices
before `</head>`, skipping any page that already contains `rel="icon"`), `'component'`
(`<Head />`), and `false` (log the block for pasting). Prefix `config.base`. Keep
`sizes="32x32"` on the ICO link or Chrome prefers it over the SVG. `logo.svg` is not linked.

## 8. Build-out plan

Sequenced. Items 4 and 5 come before 2 and 3 because they are the safety net for them.

**1. Drop icotool.** `icoWrap(png, px)` — ~15 lines of `Buffer.writeUInt*LE` per §5 — replaces the
`icotool` spawn. Before deleting anything, verify byte-identity against `icotool -c -r` on a real
corpus.

**4. Tests.** Port every definition-of-done item to `node --test`, dropping bash *and* ImageMagick.
ImageMagick is no longer preinstalled on `ubuntu-24.04` and apt's version is IM6 with no `magick`
binary, so a shell suite fails confusingly on a fresh runner. Replace it with Node: read the
33-byte IHDR for dimensions and colour type; synthesise the deliberately-wrong image with
`zlib.deflateSync`; decode with `zlib.inflateSync` + unfilter (plus PLTE/tRNS expansion for indexed
candidates) for the accuracy gate. Add the ICO-equivalence test, skipping cleanly when `icotool` is
absent. **Assert self-consistency — two runs, same inputs and tools, identical bytes — never golden
bytes.** apt's pngquant is 3.0.1 while local development may be 3.0.3, and they will not agree.

**5. Fixtures.** Twelve neutral SVGs, authored here, no brand content. Eight positive:

| Fixture | Must exercise |
|---|---|
| two-path general case | `role` + `aria-label` (stripped), a dead `id` (dropped), all palette rules, arcs + relative commands + `h`/`v` shorthand. The workhorse for `--var`, `--html`, `--manifest`, determinism and validation. |
| heavy geometry | ~768 floats (a squircle ring, 64 points × 2 contours), generated by a committed script with the output committed — so `floatPrecision: 1` has real error to introduce and the gate actually gates. |
| mask + `url(#…)` | A referenced id that must survive `cleanupIds` renaming, and an unreferenced one that must die. **The mask must sit outside `<defs>`**, since the suite asserts `icon.svg` contains no `<defs`. |
| CSS-animated | `@keyframes` under a `prefers-reduced-motion` guard, `var(--loop, infinite)`, geometry drawn at the rest frame. |
| flat two-colour circle | Cheap; large transparent margin makes the `--bg` alpha assertions unambiguous. Used by the `--bg` acceptance loop at `--sizes 32`. |
| cheap second mark | Differs in bytes from the first, for overwrite and late-failure staging, and the `--sizes 32` ICO-dedup test. |
| non-square viewBox | The stretch warning — currently untested. |
| radial gradient | Enough colours that the **lossless** path wins, so the ICO payload is 8-bit RGBA. This is what proves the hardcoded `wBitCount=32` right for a non-indexed payload. |

Four negative: unresolved `var()` with no fallback; a `var()` used *only* inside the animation
(must fail the `logo.svg` pass, mention `--no-animation`, and build cleanly with it); SMIL plus
`style="animation:…;opacity:.9"` (the non-motion `opacity` must survive); and a non-SVG file.

**2. Pure-Node PATH resolver** replacing `sh -c command -v`. Run once, memoised, reporting *every*
missing tool rather than stopping at the first. Four tiers: `FAVCON_RESVG`-style env overrides →
`await import('pngquant-bin')` (its default export is the binary path) → walk up for
`node_modules/.bin` (a *globally* installed favcon does not have the project's `.bin` on PATH) →
`PATH` + `PATHEXT`. Windows details that belong in code, not comments:

- Prefer `.EXE`/`.COM` over `.CMD`/`.BAT` even if `.CMD` appears earlier in `PATHEXT`.
- Strip surrounding quotes from PATH entries; try `cwd` first (CreateProcess does).
- Check `X_OK` on POSIX **only** — it is meaningless on Windows and rejects valid binaries.
- **If the resolved path ends in `.cmd`/`.bat`, spawn with `{shell: true}` and quote the arguments
  yourself.** Node ≥18.20.2 refuses to spawn those with `shell: false` (the CVE-2024-27980 fix),
  and `node_modules/.bin/*` on Windows *is* a `.cmd` shim.

Make the missing-dependency error the install documentation, and switch `-Z` to `--zopfli` here.

**3. Import svgo; export `build()`.** Delete the stringified plugin blocks and the temp config; the
plugins become plain objects. Then `export async function build(options)` returning
`{files, bytes, animated, links}`, `export class FavconError`, and at the bottom
`if (isEntryPoint(import.meta.url)) await cli(process.argv.slice(2))`. `isEntryPoint` compares
`realpathSync(process.argv[1])` with `fileURLToPath(import.meta.url)` — **not** `import.meta.main`,
which is too new for the 22.12 floor. `cli()` keeps `die()`, `warn()` and every exit code exactly
as they are; `build()` throws `FavconError` instead of exiting. No user-facing behaviour moves.
The gate: byte-identical `logo.svg` and `icon.svg` on every fixture.

**7. CI.** Pin **`ubuntu-24.04`**, never `ubuntu-latest` — an image flip silently changes the apt
pngquant version and therefore output bytes. Install resvg and oxipng from **pinned release
tarballs**, not `cargo install` (2–5 minutes each): tarballs land in seconds and pin the exact
toolchain the measurements assume. `apt install pngquant icoutils` (icoutils solely so the ICO
equivalence test runs rather than skips). Add `macos-15` — brew has all three, and it is the job
that catches `pngquant-bin`'s missing `darwin/arm64`. Add a **`windows-latest` smoke job** covering
everything that needs no rasteriser: argument parsing, the PATH resolver, both svgo passes, the ICO
writer unit test, staging, atomic rename and cleanup. Full Windows waits — upstream resvg stopped
shipping `resvg-win64.zip` after v0.47.0, so the only route is a cached `cargo install`. Add a
fourth job asserting `npm pack --dry-run` contains `bin/` and `astro/` and **nothing** from
`test/`, `docs/`, `bench/` or `.github/`.

**6. Astro integration** per §7. Cache layer first, then the hooks, then middleware and `Head.astro`.

**8. Benchmarks.** One `bench/bench.mjs` sweeping the pipeline axes (dither, colours, stage order,
zopfli iterations, ICO container) over `test/fixtures/`, printing a table and regenerating
`docs/BENCHMARKS.md`. Scratch output is gitignored.

**9. README.** 30-second quickstart; the output table with real byte counts; an honest "why not X"
naming `favicons` (388k weekly downloads, sharp-based), `astro-favicons` (4.1k/wk) and `favgen`
(5/wk) — **none of them recompress**, which is the whole point; the install matrix for the three
external binaries; the full flag reference; the Astro section; and a short "how it decides" linking
`docs/DECISIONS.md`.

## 9. Definition of done

`test/run.mjs` automates every line.

1. Produces exactly `logo.svg`, `icon.svg`, `favicon.ico`, `apple-touch-icon.png`, `icon-192.png`,
   `icon-512.png` — and nothing else.
2. Dimensions are exact: 180×180, 192×192, 512×512; the ICO reports a single 32×32 entry.
3. `icon.svg` — in **every** mode, including a default build of an animated source — contains no
   `role`, no `aria-*`, no `class`, no `style=`, no `<style>`, no `<defs`, no `var(`, and keeps
   `xmlns` and `viewBox`.
4. `--var name=value` overrides the fallback, and the old value is gone from the output.
5. An unresolvable `var()` with no fallback fails loudly with a non-zero exit, and writes nothing.
6. A referenced id survives; unreferenced ids are dropped.
7. `favicon.ico` starts `00 00 01 00`, its payload is a PNG (`89 50 4E 47`), and the container is
   byte-identical to `icotool -c -r` wherever icotool is available.
8. Every emitted raster meets `pct <= 1.0 %`; the padded icons are scored against
   **background-matched, identically padded** references.
9. `apple-touch-icon.png` has no alpha channel when `--bg` is set (the default).
10. `--manifest` writes valid JSON: the size icons as `"any maskable"` when `--bg` is opaque
    and `"any"` alone when it is `none`, and never `icon.svg`; `--html` emits the `<link>` set with
    `sizes="32x32"` on the ICO.
    Every opaque pixel of every padded icon lies inside the safe circle; a pixel-grid mark is
    snapped to whole pixels, a curved one keeps its exact fit.
11. Re-running with identical inputs and identical tool versions produces byte-identical outputs.
12. Temp files are removed on success **and** on failure; a failed run leaves any previous output
    set intact, and leaves no staging directory behind.
13. `--colors` outside 2–256, a missing input, a non-SVG input and an unknown flag all fail with a
    clear `favcon: …` message and **no stack trace**.
14. Animation lands in `logo.svg` and nowhere else: it keeps its reduced-motion guard, has `var()`
    resolved inside it, carries no `role`/`aria-*`, and every surviving class is a live selector.
    `--no-animation` makes `logo.svg` equal `icon.svg`; a static source does the same. `icon.svg`
    equals the same source with its animation deleted and is byte-identical in both modes — as is
    every raster. A `var()` used only by an animation fails the `logo.svg` pass, naming
    `--no-animation`, and never the `icon.svg` one.
15. Long options accept `--opt=value`; a flag that takes no argument rejects one.
16. `--sizes 32` renders twice on purpose: once padded for `icon-32.png`, once unpadded for
    the ICO payload. Under `--bg none` the icon is unpadded too, and the two are the same
    bytes again.
17. A non-square viewBox warns on stderr.
18. `npm pack` contains only `bin/`, `lib/`, `astro/`, `README.md`, `LICENSE`, `CHANGELOG.md` —
    and `lib/core.mjs` by name, since the package cannot run without it.

## 10. Conventions

- **Every pipeline change arrives with a number.** If a change touches the optimisation path, it
  comes with a `bench/bench.mjs` run showing the byte delta and proof that every fixture is still
  inside the accuracy bar. "Looks the same" is not evidence. A change that costs bytes to save
  build time is rejected by default — see the Priority note in §3.
- **Measure before you believe it.** Decision 13 exists because an obvious-looking parallelism win
  was 12.8 s → 8.1 s in a quick hand test and **13.80 s → 14.08 s** under a controlled interleaved
  benchmark. Interleave repetitions, check for background load, and prefer tracing over totals.
- **Comments explain *why*, and cite the measurement.** The code is dense in places because the
  obvious version is wrong; a reader must be able to find out why without a git archaeology trip.
- No new CLI flags without a stated user need. The surface is deliberately small.
- `bin/favcon.mjs` stays **one file** for everything only it does — tool resolution, spawning,
  staging, `build()`, `cli()`. The one exception is `lib/core.mjs`, the isomorphic half the
  website also runs; see decision 21. The Astro integration may import either; neither may
  ever import the Astro integration.
- Errors are `favcon: <message>` on stderr with a non-zero exit — never a raw stack trace.

## 11. Release

`npm version <patch|minor|major>` → push the tag → `release.yml` publishes from GitHub Actions with
`permissions: {id-token: write}` for provenance. Keep `CHANGELOG.md` in Keep-a-Changelog form.
Byte-output changes — a bumped resvg, pngquant or oxipng, or any pipeline change — are **minor at
minimum**, never patch: downstream users diff these files into git.
